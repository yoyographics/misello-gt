# PROMPT 1 — AUTHENTICATION MODULE

```
Context: You are working on the NestJS backend of the misello.gt project. The base structure is already created (Prompt 0 completed). Read the file misello-gt-master-brief-v2-EN.md for full context.

YOUR TASK: Create Module 1 — Authentication — complete, in `src/auth/`.

This module handles TWO completely different types of users:

---

PART A — PUBLIC CUSTOMERS (Google OAuth)

Site customers can ONLY authenticate with Google. There is no username/password for them.

Implement:

1. `GoogleStrategy` (passport-google-oauth20):
   - Scopes: email, profile
   - When Google returns the user profile, search the `User` table by `googleId`
   - If not found → automatically create the user with Google data (email, name, picture)
   - If found → update name and picture in case they changed
   - Return the database user

2. Public endpoints (no authentication required to access):
   - `GET /auth/google` → redirects to Google authentication flow
   - `GET /auth/google/callback` → Google callback, creates JWT session and redirects to frontend with token

3. JWT generated for public customers contains:
   - sub: user id
   - email
   - role: 'CLIENT'
   - expiration: 30 days

4. Create `JwtClientGuard` — guard that verifies the JWT token belongs to a customer (role === 'CLIENT')

---

PART B — INTERNAL PANEL USERS (JWT with username/password)

Panel users have their own independent login system.

Implement:

1. Endpoint `POST /auth/admin/login`:
   - Body: { email: string, password: string }
   - Validate with class-validator (both fields required, valid email format)
   - Find AdminUser by email
   - If not found or `isActive === false` → respond 401 with generic message (do not reveal whether the email exists)
   - Verify password against stored hash using bcrypt
   - If correct → generate JWT with: sub, email, name, role, expiration 8 hours
   - If incorrect → respond 401 with generic message

2. MANDATORY RATE LIMITING on this endpoint:
   - Maximum 5 attempts per IP in 15 minutes
   - If exceeded → respond 429 with message: "Too many attempts. Please try again in 15 minutes."
   - Use @nestjs/throttler for this

3. Create `JwtAdminGuard` — guard that verifies the token belongs to an admin and that the AdminUser is still active in the database.

4. Create `RolesGuard` — guard that verifies the user's role has permission to access the endpoint. Create `@Roles(...roles)` decorator to use in controllers.

5. Endpoint `GET /auth/admin/me` (requires JwtAdminGuard):
   - Returns the authenticated user's data (without passwordHash)

6. Endpoint `POST /auth/admin/logout` (requires JwtAdminGuard):
   - For now just returns 200 OK (actual logout is done by deleting the token on the frontend)

---

PART C — SHARED UTILITIES

1. Create an `AuthService` with methods:
   - `generateClientToken(user)` → generates client JWT
   - `generateAdminToken(adminUser)` → generates admin JWT
   - `hashPassword(password)` → generates bcrypt hash (saltRounds: 12)
   - `comparePassword(plain, hash)` → compares password with hash

2. Create a script `src/scripts/create-admin.ts` that can be run with `npx ts-node` to create the first administrator user from the terminal. The script asks for email, name, and password, and creates the AdminUser with ADMIN role. This script is for one-time use by the IT team.

---

ADDITIONAL SECURITY CONFIGURATION:
- The auth module throttler has a stricter configuration than the global one:
  - Admin login: max 5 attempts / 15 minutes per IP
  - Google OAuth endpoints: max 20 requests / minute per IP

RULES:
- All authentication error messages are GENERIC (do not reveal whether the email exists)
- Passwords are never logged to console
- JWT tokens are never stored in the database (stateless)
- Use environment variables for: GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_CALLBACK_URL, JWT_SECRET, JWT_EXPIRATION

When done, show me the created endpoints with their HTTP methods and full routes.

# PROMPT 3 — DESIGN ASSISTANT MODULE

```
Context: You are working on the NestJS backend of the misello.gt project. Modules 0, 1, and 2 are already created. Read the file misello-gt-master-brief-v2-EN.md for full context.

     productId: string,         // ID of the chosen stamp model

     textLines: string[],       // Stamp text lines (max 6 lines)
     textCurved: boolean,       // Whether any line goes in an arc
     curvedLines: number[],     // Indexes of lines that go in an arc
     logoIncluded: boolean,     // Whether it includes a logo
     logoUrl?: string,          // URL of the already-uploaded logo (if applicable)

     isLawyerReplica: boolean,  // Whether it is a lawyer stamp replica
     referencePhotoUrl?: string // URL of previous stamp photo (if replica)
   }

   """
   You are the design assistant for misello.gt, specialized in laser rubber stamps. Your only function is to analyze an order's parameters and return a structured JSON with the technical design parameters. You NEVER generate the SVG directly. You ALWAYS return only valid JSON, without additional text, without markdown, without explanations.

   The JSON you must return has this exact structure:
   {
     "layout": "single_centered" | "two_lines" | "multi_line" | "circular_text" | "oval_layout",
     "textBlocks": [
       {
         "text": "line text",
         "fontSize": number in points (minimum 8pt),
         "fontWeight": "regular" | "bold",
         "alignment": "center" | "left" | "right",
         "curved": boolean,
         "curveRadius": number in px (only if curved=true),
         "curveDirection": "top" | "bottom" (only if curved=true),
         "yPosition": percentage of vertical position (0-100),
         "letterSpacing": number (0 = normal)
       }
     ],
     "logoPlacement": null | {
       "position": "top" | "center" | "left" | "right",
       "widthPercent": percentage of total stamp width (5-40),
       "yPosition": percentage of vertical position
     },
     "borderStyle": "none" | "single" | "double" | "thick",
     "borderThickness": number in px,
     "innerMarginPx": number (minimum 20px),
     "designNotes": "technical observations if any"
   }

   MANDATORY technical constraints you must respect:
   - Minimum font size: the smallest text must be legible at 600dpi (minimum equivalent to 2mm height)
   - For very small models (less than 20mm tall) use larger fonts
   - The design ALWAYS has a minimum internal margin of 20px on all sides
   - Text items NEVER overlap each other or with the logo
   - For circular and oval stamps, the main text is centered or follows the shape in an arc
   - For lawyer stamp replicas: respect the original layout from the reference photo
   """

   The user message sent to Claude includes:
   - Model dimensions in px (widthPx, heightPx)
   - Stamp shape (rectangular, circular, oval)

   - Whether it includes a logo and preferred position
   - Stamp category
   - If replica, description of the reference photo

1. **Production SVG** (black and white, 600 dpi, exact model size in px):
   - Background: white (#FFFFFF)
   - All elements: black (#000000)
   - If logo has colors/gradients → convert to B&W using sharp before embedding
   - SVG dimensions are exactly widthPx × heightPx of the model
   - Text uses the font specified in designJson (from uploads/fonts/ folder)

   - Same layout as the production SVG

4. Return the URLs of both files
